# Задание для Claude Code: рефакторинг spisokradosti

## Контекст

Репозиторий: https://github.com/codenol/spisokradosti  
Деплой: https://codenol.github.io/spisokradosti/

Текущее приложение — «Список желаний» с картой, маршрутами и совместным доступом.  
Задача: переориентировать его под **планирование прогулок и поездок** — личных и совместных.

**Стек и требования:**
- Mobile first, PWA
- Есть пользователи на iOS — учитывать ограничения Safari/iOS PWA
- На десктопе всё крупно: single-column wide, крупные карточки, большие кнопки
- Touch-таргеты минимум 44×44pt
- Никакого hover-only UI

---

## Новая архитектура данных

Ниже — полная структура. Внедряй постепенно, не ломая существующие данные пользователей.

### Place — Место
```js
{
  id,
  name,
  type: 'museum' | 'cafe' | 'restaurant' | 'park' | 'hotel' | 'other',
  coordinates: { lat, lng },
  address,

  // Метро (опционально, массив — место может быть у нескольких станций)
  metro_stations: [
    {
      name: string,         // «Третьяковская»
      line: string,         // «Калужско-Рижская» (опц.)
      line_color: string,   // hex-цвет линии (опц.)
      exit: string | null   // «выход 2» (опц.)
    }
  ],

  // Статус в вишлисте
  status: 'wishlist' | 'visited',
  priority: 'low' | 'medium' | 'high',

  // Оценка и проблемы
  rating: null | 1 | 2 | 3 | 4 | 5,
  flags: Array<'booking_required' | 'seasonal' | 'crowded' | 'closed' | 'expensive' | 'note'>,
  comment: string,

  // Цены (опц.)
  price_range: null | 'budget' | 'mid' | 'expensive',
  price_note: string,

  // Мета
  added_by: user_id,
  added_at: timestamp,
  visits: Visit[]
}
```

### Visit — Визит
```js
{
  id,
  place_id,
  trip_id: string | null,   // если в рамках поездки
  date,
  rating: null | 1 | 2 | 3 | 4 | 5,
  comment: string,
  user_id
}
```

### Template — Шаблон маршрута (без дат, переиспользуемый)
```js
{
  id,
  name,
  type: 'walk' | 'day_trip' | 'multiday',
  days: TemplateDay[],

  created_by: user_id,
  source_template_id: string | null,  // если форкнут из другого шаблона
  created_at: timestamp,
  used_count: number
}
```

### TemplateDay
```js
{
  day_number: number,
  title: string | null,
  items: TemplateItem[]
}
```

### TemplateItem
```js
{
  id,
  place_id,
  slot: 'morning' | 'afternoon' | 'evening' | null,
  duration_minutes: number | null,
  note: string | null,
  order: number
}
```

### Trip — Поездка (экземпляр шаблона или созданная с нуля)
```js
{
  id,
  name,
  source_template_id: string | null,
  status: 'draft' | 'upcoming' | 'active' | 'done',

  date_start: date | null,
  date_end: date | null,

  participants: TripMember[],
  days: TripDay[],
  accommodations: Accommodation[],

  // Кэшированный бюджет, пересчитывается при изменениях
  budget_summary: { per_person: number, total: number } | null,

  created_by: user_id,
  created_at: timestamp
}
```

### TripMember
```js
{
  user_id,
  role: 'owner' | 'editor' | 'viewer',
  joined_at: timestamp
}
```

### TripDay
```js
{
  id,
  trip_id,
  day_number: number,
  date: date | null,
  title: string | null,
  
  // Старт дня (для метромаршрута)
  start_metro_station: string | null,  // название станции
  start_address: string | null,

  items: TripItem[]
}
```

### TripItem
```js
{
  id,
  place_id,
  slot: 'morning' | 'afternoon' | 'evening' | null,
  time: string | null,           // «10:00»
  duration_minutes: number | null,
  note: string | null,
  order: number,
  added_by: user_id,
  votes: { user_id: string, value: 1 }[]
}
```

### Accommodation — Жильё
```js
{
  id,
  trip_id,
  name,
  date_checkin: date,
  date_checkout: date,
  price_per_night: number | null,
  currency: string,              // «RUB», «EUR» и т.д.
  booking_url: string | null,
  note: string | null
}
```

## Навигация

Заменить текущую навигацию на bottom bar с 4 табами:

```
[ Места ]  [ Шаблоны ]  [ Поездки ]  [ Гуляю ]
```

«Гуляю» — крайний справа, самый важный для спонтанного использования.

---

## Экраны и поведение

### Таб: Места

Переименовать «Список желаний» → «Мои места».

Фильтры вверху:
- `[ Все | Хочу | Был ]`
- `[ Фильтр по типу ]` — горизонтальный скролл чипов

Карточка места в списке:
- Название, тип, район
- Рейтинг звёздами (если есть)
- Флаги проблем иконками (📅 👥 ❌ 💸 ℹ️)

**Детальный экран места:**
- Название, тип, рейтинг
- Блок «Флаги»: типизированные иконки + текст. Флагов может быть несколько
- Комментарий
- Метро: список станций с цветом линии и номером выхода
- Карта (небольшая, тапабельная — открывает полную)
- История визитов: дата + оценка + комментарий
- Кнопки: `[ + В шаблон ]` `[ + В поездку ]`

**Флаги (типизированные):**
| Код | Иконка | Текст |
|-----|--------|-------|
| `booking_required` | 📅 | Нужна бронь |
| `seasonal` | 🌿 | Сезонное |
| `crowded` | 👥 | Бывает людно |
| `closed` | ❌ | Закрыто / изменилось |
| `expensive` | 💸 | Дороже ожиданий |
| `note` | ℹ️ | Нюанс |

**Важно по оценкам:**
- Глобальная оценка места — среднее по собственным визитам пользователя
- Оценки других пользователей не влияют на глобальную оценку
- Оценка визита — личная для каждого участника поездки

---

### Таб: Шаблоны

Список шаблонов. Карточка:
- Название, тип (прогулка / день / многодневный)
- Количество мест
- Сколько раз запускался
- Кнопки: `[ Запустить ]` `[ ··· ]`

**Экран «Запустить шаблон»:**
1. Выбрать дату начала (или диапазон для многодневных)
2. Добавить участников (опц.)
3. Если в шаблоне есть места с флагом `closed` — предупреждение:
   > ⚠️ В шаблоне есть места с проблемами: Кафе X — отмечено как закрытое. Убрать или оставить?
4. Опция «Изменить маршрут перед созданием»
5. Кнопка `[ Создать поездку ]`

После запуска — шаблон и поездка независимы. Изменение шаблона не меняет уже созданные поездки.

Опция в меню поездки: `[ Сохранить как новый шаблон ]` — позволяет форкнуть поездку обратно в шаблон. Сохраняет `source_template_id`.

---

### Таб: Поездки

Подтабы: `[ Предстоящие | Прошедшие ]`

Карточка поездки:
- Название, даты
- Участники (аватарки, максимум 3 + «+N»)
- Количество дней и мест
- Статус жилья (🏨 если добавлено)

**Детальный экран поездки — три таба:**

#### Таб «Дни»

По каждому дню:
- Заголовок: «День 1 · 22 марта»
- Список мест в порядке посещения
- Каждое место: время, название, флаги, кто добавил (аватарка), голоса ❤️
- Кнопка `[ + Место в день N ]`

Кнопки маршрута внизу (показываются если выбран день):
```
[ 🗺 На карте ]  [ 🚇 На метро ]  [ Открыть в Google Maps ]
```

#### Таб «Карта»

Все места поездки на карте. Маркеры по дням (разные цвета).

#### Таб «Бюджет»

- Секция «Жильё»: для каждого Accommodation — название, даты, цена/ночь, итого за N ночей, итого на M человек
- Секция «Еда» (оценка): среднее по price_range мест × количество дней
- Итоговая строка: ~X ₽ на человека
- Кнопка `[ + Жильё ]`

---

### Таб: Гуляю

Режим спонтанной прогулки.

1. Геолокация
2. Если город — Москва или Санкт-Петербург (определяется по координатам) и рядом есть метро (< 800м):
   - Показать: «Вы у метро [Название]»
   - Кнопки: `[ Показать места пешком ]` `[ Маршрут от [Станция] ]`
3. Иначе — обычный пешеходный режим

Список мест из вишлиста в радиусе N км:
- Расстояние
- Флаги проблем
- Чекбокс для добавления в маршрут

Нижняя панель (появляется при выборе мест):
```
[ Выбрано: 2 ]
[ Построить маршрут ]
```

## Метро — логика

### Где применяется
Только для Москвы и Санкт-Петербурга. Определять по bbox координат.

### MVP-подход (не требует transit API)
- Станции метро у мест хранятся вручную (пользователь указывает при добавлении/редактировании)
- Маршрут «на метро» строится как: последовательность станций на основе данных мест + deep link в Google Maps / Яндекс Карты с `travelmode=transit`
- В приложении показываем: откуда → какая ветка → сколько остановок → пешком сколько → следующая точка

### Отображение в маршруте дня
```
🚇 Старт: Площадь Восстания
↓ [линия · N остановок]
🚇 Гостиный Двор → выход 2
↓ пешком 400м · 5 мин
📍 Эрмитаж
```

### Старт дня в поездке
При планировании каждого дня — запрашивать стартовую точку:
- От метро → выбрать станцию
- От адреса
- Пропустить

Если в поездке указано жильё — его адрес предлагается по умолчанию как старт следующего дня.

## Совместный доступ

- Роли: `owner` / `editor` / `viewer`
- Рядом с каждым местом в поездке — аватарка того, кто добавил
- Голосование: ❤️ на каждом месте, суммируется по участникам
- Организатор может включить «режим голосования»: участники голосуют, потом места сортируются по голосам. Топ → в маршрут, остальные → резерв
- Синхронизация: pull (не push, из-за ограничений iOS PWA). Обновление при открытии экрана
- Приглашение через ссылку

## Приоритет работ

Рекомендуемый порядок:

1. **Структура данных** — добавить новые модели (Template, Trip, Accommodation), обновить Place (metro_stations, flags). Обеспечить обратную совместимость со старыми данными
2. **Навигация** — новый bottom bar, 4 таба
3. **Места** — детальный экран с флагами и метро
4. **Поездки** — CRUD, дни, участники
5. **Шаблоны** — CRUD, запуск, форк
6. **Гуляю** — улучшить существующий режим, добавить метро-старт
7. **Бюджет** — калькулятор на основе жилья и ресторанов
8. **Голосование** — режим для совместного выбора мест
